## 1. 产品定位

你要做的不是传统意义上的“AI 自动写剧本杀”，也不是普通 AI 聊天网页，而是一款：

> **基于固定精品剧本的 AI 沉浸式悬疑互动游戏。**

### 1.1 核心体验

1. 玩家进入一个已经写好的悬疑案件。
2. 由 **AI DM** 控场。
3. 由 **AI 角色** 扮演其他玩家 / 嫌疑人。
4. 用户自己选择一个身份参与推理。
5. 通过对话、证物、线索、场景探索推进剧情。
6. 最终指认真凶、动机和关键证据。
7. 结尾由系统完成真相揭示、复盘评分和遗漏线索回看。

> **关键判断：** 产品不是“AI 生成故事”，而是让 AI 在固定剧本框架内进行沉浸式演绎和流程控制。

### 1.2 当前素材包对应的产品方向

`Organizing/` 目录已经不只是剧本文字，而是一套完整的线上游戏素材包，包含：

- 两组角色个人剧本 PDF。
- 分轮次线索图。
- 技能卡、道具卡。
- 开本音频、结局音频、广播和童谣音频。
- 主海报、人物海报、宣传视频。
- DM 带本资料、最终演绎要点、调查问卷。
- 线上证物图片、技能卡和道具卡素材。

因此系统设计应从“单纯 AI 对话游戏”升级为：

> **可导入固定剧本素材包、可控阶段推进、可管理多媒体与线上证物道具的 AI 剧本杀系统。**

## 2. 核心目标与边界

本产品的核心目标是：保护精品剧本的确定性，同时用 AI 增强互动自由度、沉浸感和复盘体验。

### 2.1 你已有的内容资产

| 剧本内容 | 互动 / 多媒体内容 | 运营 / 开本资料 |
| --- | --- | --- |
| 案件背景 | 证据 / 线索图 | DM 带本要点 |
| 人物设定 | 道具 / 道具卡 | 最终演绎要点 |
| 真相 | 场景 | 调查问卷 |
| 凶手 | 阶段流程 | 售后资料 |
| 动机 | 结局揭示 | 宣传素材 |
| 关键线索 | 背景音乐 | 宣传视频 |
| 故事章节 | 人物语音 / 关键音频 | 人物海报 |
| 玩家个人剧本 | 技能卡 | 主海报 |

> **边界：** AI 不负责重新编剧本，不负责随意改写主线剧情。

### 2.2 AI 的作用

| AI 主要负责 | AI 不应该负责 |
| --- | --- |
| 扮演 NPC / 其他玩家 | 改变凶手 |
| 扮演 DM | 改变动机 |
| 根据玩家提问做自然回应 | 新增关键证据 |
| 按当前阶段和角色权限提供信息 | 擅自编造主线剧情 |
| 控制剧情流程推进 | 提前透露真相 |
| 根据证物和线索触发角色反应 | 破坏剧本设定 |
| 陪玩家推理 | 把未解锁线索主动说出 |
| 做最终复盘和评分 | 把售后 / DM 资料暴露给玩家 |

### 2.3 内容整合原则

1. **剧本事实优先：** 角色剧本、DM 带本资料、最终演绎要点是真相和演绎边界的最高依据。
2. **阶段权限优先：** 线索图、音频、角色对话必须绑定到具体幕、轮次、阶段。
3. **素材不粗暴堆叠：** 音频归入多媒体系统，证物、道具卡和图片素材归入证物 / 道具系统，带本要点归入售后资料管理。
4. **玩家可见与后台可见分离：** 玩家只看到当前阶段应出现的信息；DM、Guard Agent 和后台管理可读取更多完整资料。
5. **线上证物与道具卡结构化管理：** 所有证物、道具卡、技能卡和图片素材都应绑定数字记录、触发阶段、可见权限和交互规则。

## 3. 游戏核心玩法

玩家选择一个角色 / 身份进入案件；除真人玩家外，其余关键角色由 AI 扮演，并由 **AI DM** 统一控场。

### 3.1 玩家身份

系统中至少包含以下参与方：

| 参与方 | 说明 |
| --- | --- |
| 真人玩家 | 选择一个角色 / 身份参与推理。 |
| AI DM | 负责主持、叙事、流程推进与最终复盘。 |
| 多个 AI 角色 / NPC | 扮演其他玩家或嫌疑人，根据角色知识边界回应。 |
| Guard Agent | 隐藏审查智能体，检查 AI 输出是否剧透、编造或越权。 |
| 内容后台 | 供管理员导入剧本、线索、音频、图片、道具和开本资料。 |

### 3.2 AI DM

**AI DM** 是游戏主持人和流程控制器，知道完整真相，但不能直接告诉玩家。

| DM 职责 | 说明 |
| --- | --- |
| 开场介绍 | 建立案件背景与悬疑氛围。 |
| 场景切换 | 引导玩家进入不同调查空间。 |
| 背景旁白 | 用叙事语言补充现场信息。 |
| 阶段推进 | 根据条件推进主线阶段。 |
| 线索触发 | 判断玩家行为是否触发新线索。 |
| 证物解锁 | 在合适阶段开放证物。 |
| 音频调度 | 在开场、广播、童谣、结局等节点播放对应音频。 |
| 信息权限控制 | 控制 AI 角色是否可以透露某些信息。 |
| 最终推理判定 | 判断玩家提交的真凶、动机、证据和推理链条。 |
| 真相揭示 | 在结尾阶段揭露完整真相。 |
| 游戏复盘 | 输出评分、遗漏线索和最优推理路径。 |

> **定位：** DM 是系统中的最高控场智能体，但其输出必须经过阶段状态和防剧透规则约束。

### 3.3 AI 角色 / NPC

每个 AI 角色都有独立身份和行为边界，不能拿到全部剧本真相，只能拿到自己当前应该知道的信息。

| 角色信息 | 说明 |
| --- | --- |
| 姓名 | 角色的展示名称。 |
| 身份 | 在案件中的身份、社会关系或玩家身份。 |
| 所属剧本 | 角色属于第一本、第二本或跨本角色。 |
| 性格 | 决定对话风格、情绪反应和行为倾向。 |
| 公开背景 | 玩家可逐步了解到的公开信息。 |
| 私密秘密 | 角色可能隐瞒、回避或被揭露的信息。 |
| 是否凶手 | 是否为案件真凶。 |
| 动机 | 角色可能涉及的动机或嫌疑来源。 |
| 知道哪些信息 | 当前阶段允许进入 Prompt 的角色知识。 |
| 不知道哪些信息 | 禁止角色主动提及或假装知道的信息。 |
| 不同阶段能说什么 | 与阶段、线索解锁和角色权限绑定。 |
| 面对不同证物的反应 | 出示证物后触发的态度变化、说辞或破绽。 |
| 对技能卡 / 道具卡反应 | 玩家使用特殊卡牌时，角色可触发的回答或行为变化。 |

## 5. 游戏流程设计

建议采用 **固定主线 + 半开放调查** 的结构：

> 主线阶段固定；每个阶段内允许玩家自由询问、探索、出示证物；达到条件后由 **AI DM** 推进下一阶段。

### 5.1 通用游戏阶段

| 阶段 | 名称 | 功能 / 产出 |
| --- | --- | --- |
| 阶段 0 | 序章 | 展示案件封面；播放开场 BGM；播放 DM 旁白；简要介绍案件背景；玩家选择身份。 |
| 阶段 1 | 案发现场 | 进入第一个固定场景；展示背景图；播放场景音乐；DM 介绍现场；用户点击可疑物品；解锁第一批证物。 |
| 阶段 2 | 初步问询 | 用户选择角色对话；AI 角色根据身份和当前阶段回答；角色不能透露未解锁信息；用户可以记录笔记；可发现轻微矛盾。 |
| 阶段 3 | 证物调查 | 用户查看证物；深入调查证物；将证物出示给不同角色；触发角色反应；解锁新线索；更新证物状态。 |
| 阶段 4 | 角色对峙 | 用户根据已有证物追问关键角色；AI 角色可能回避、撒谎、破防；DM 判断是否触发关键矛盾；进入最终推理前的准备阶段。 |
| 阶段 5 | 最终推理 | 用户提交真凶、动机、关键证据和推理链条；系统根据剧本真相和已解锁线索判定结果。 |
| 阶段 6 | 真相揭示 | 播放真相 BGM；DM 语音揭示真相；凶手 / 关键角色最终独白；展示完整作案过程；展示用户遗漏线索。 |
| 阶段 7 | 复盘评分 | 生成推理评分、破案用时、关键线索命中率、误判次数、最优推理路径、遗漏证据和彩蛋结局。 |

每个阶段不应只依赖“点击下一步”，应支持条件式推进：

| 推进条件 | 示例 |
| --- | --- |
| 时间条件 | 当前阶段达到推荐体验时长后，DM 可提醒进入下一阶段。 |
| 线索条件 | 玩家已查看本轮关键线索数量达到阈值。 |
| 对话条件 | 玩家已询问关键角色或触发关键矛盾。 |
| 证物条件 | 玩家已查看 / 出示关键证物。 |
| DM 手动条件 | 玩家请求推进，DM 判断不会破坏体验后进入下一阶段。 |
| 强制剧情条件 | 播放广播、童谣、撞车、手机线上等固定剧情音频后推进。 |

## 6. 场景系统

场景不是纯背景图，而是可交互区域；每个固定场景都应承载探索、证物、角色和剧情触发。

### 6.1 场景字段

| 字段 | 说明 |
| --- | --- |
| 场景名称 | 场景的展示名称，例如案发客厅、雪乡村口、民宿、广播站。 |
| 背景图片 | 用于营造视觉氛围。 |
| 背景音乐 | 与场景 / 阶段绑定的 BGM。 |
| DM 进入旁白 | 玩家进入场景时触发的旁白。 |
| 可点击热点 | 玩家可调查的交互区域。 |
| 可发现证物 | 当前场景中可被解锁的证物。 |
| 可出现角色 | 当前场景允许出现或可对话的角色。 |
| 可触发剧情 | 调查、对话或出示证物后触发的剧情节点。 |
| 当前阶段是否开放 | 控制场景是否可进入。 |
| 关联线索轮次 | 指向第一幕第一轮、第二本第二轮等线索包。 |
| 关联音频 | 进入场景或事件发生时播放的音频。 |

### 6.2 场景示例

| 场景类型 | 示例 | 说明 |
| --- | --- | --- |
| 案发核心场景 | 案发客厅、卧室、密室 | 承载尸体、凶器、关键证物和首次搜证。 |

| 隐藏 / 深层场景 | 地下室、仓库、林地 | 在后续阶段解锁，用于关键反转。 |

### 6.3 场景与线索绑定

线索图目前按轮次归档，系统导入后需要进一步标注其“出现位置”：

1. 每张线索图必须绑定一个阶段。
2. 每张线索图最好绑定一个场景或事件。
3. 个人线索必须绑定角色权限。
4. 无法确定场景的线索先归入“本轮公共线索池”，后续再人工精修。

## 10. AI 对话系统

AI 对话是半开放的：玩家可以自由问角色问题，但 AI 回答必须遵守剧本事实、阶段权限和防剧透规则。

### 10.1 回答约束

| 约束 | 说明 |
| --- | --- |
| 当前阶段 | 只允许回答当前阶段可见内容。 |
| 当前角色身份 | 回答必须符合角色身份和性格。 |
| 当前角色知识范围 | 角色只能说自己应该知道的信息。 |
| 已解锁线索 | 未解锁线索不能进入回答。 |
| 已发现证物 | 未发现证物不能被角色主动提及。 |
| 剧本事实 | 不允许偏离固定剧本设定。 |
| 禁止剧透规则 | 不允许提前透露真相或关键结论。 |
| 售后资料隔离 | 带本要点、最终演绎要点不能直接暴露给玩家。 |

### 10.2 每次玩家提问流程

1. 玩家输入问题。
2. 后端读取当前游戏状态。
3. 判断对话对象。
4. 检索该角色可见信息。
5. 检索当前阶段可见线索。
6. 检索已发现证物和已播放剧情事件。
7. 组装角色 **Prompt**。
8. AI 角色生成回答。
9. **Guard Agent** 检查是否剧透 / 编造。
10. 如果违规，要求重写。
11. DM 判断是否触发新线索、证物状态变化或阶段推进。
12. 写入聊天记录。
13. 返回给玩家。

### 10.3 Prompt 组装结构

| Prompt 层 | 内容 |
| --- | --- |
| 系统规则 | 不剧透、不编造、不越权、保持角色口吻。 |
| 角色身份 | 姓名、性格、关系、公开背景。 |
| 当前阶段 | 幕、轮次、可见线索、已发生事件。 |
| 角色私有知识 | 只包含该角色当前阶段应知道的个人剧本内容。 |
| 玩家已知状态 | 已发现线索、已查看证物、已对话角色。 |
| 禁止信息 | 未解锁真相、其他角色私密剧本、售后资料。 |
| 输出要求 | 简洁、符合情绪、可追问、不直接给结论。 |

## 11. 防剧透机制

防剧透机制是系统稳定性的关键，至少需要三层防护。

### 11.1 第一层：数据隔离

每个角色只拿到自己知道的信息。

> **禁止：** 不能把完整真相塞给所有角色。

### 11.2 第二层：阶段过滤

未到阶段的线索不能进入 **Prompt**。即使数据库中已有全部素材，也必须按以下条件过滤：

- 当前幕 / 轮次。
- 玩家是否已获得该线索。
- 当前角色是否有权限知道该线索。
- 当前对话是否有合理触发条件。

### 11.3 第三层：Guard Agent 审查

AI 生成回答后，由隐藏审查 Agent 检查：

- 是否提前透露真凶。
- 是否提前透露动机。
- 是否提到未解锁证物。
- 是否编造新角色。
- 是否改变剧本事实。
- 是否越过当前阶段。
- 是否违反角色知识边界。
- 是否误把带本要点、最终演绎要点当成玩家可见内容。

如果违规，重新生成。

### 11.4 第四层：最终输出白名单

关键阶段建议使用更严格的输出控制：

| 场景 | 控制方式 |
| --- | --- |
| 开场旁白 | 可使用固定文案或审核后的 DM 文案。 |
| 关键线索发放 | 只展示后台配置的线索内容，不让 AI 自由生成。 |
| 结局揭示 | 优先使用固定真相文本和结局音频。 |
| 评分复盘 | AI 可生成表达，但判断依据必须来自结构化答案表。 |

| 宣传视频 | 剧本详情页、营销页 | 不应包含会剧透的未审核片段。 |

### 12.3 素材状态管理

每个素材都需要有状态，避免未完成文件进入正式游戏：

| 状态 | 含义 |
| --- | --- |
| 待处理 | 文件已存在，但尚未 OCR、转写、压缩或标注。 |
| 已转写 | PDF、DOCX、图片或音频已提取文本。 |
| 已标注 | 已绑定阶段、角色、场景、权限。 |
| 已审核 | 内容确认无剧透错误、无错别字、可上线。 |
| 已发布 | 正式进入玩家可体验流程。 |
| 需补全 | 文件缺失、下载未完成或命名不一致。 |

## 16. 数据导入与素材处理流程

### 16.1 导入步骤

1. 扫描 `Organizing/` 目录，生成素材清单。
2. 将 PDF、DOCX、图片、音频、视频上传到 Storage。
3. 对 PDF / DOCX 提取文本，建立剧本片段。
4. 对线索图、技能卡、道具卡进行 OCR，保留原图和文字。
5. 对音频生成转写文本和字幕。
6. 按目录语义自动生成初始阶段：第一幕第一轮、第二幕第二轮、第二本第一轮等。
7. 人工审核线索内容、角色权限和阶段绑定。
8. 将道具图片、技能卡和道具卡写入线上证物 / 道具管理。
9. 标记缺失、下载中、命名不一致的素材。
10. 通过测试会话验证 AI 不剧透、流程可推进、素材可播放。

### 16.2 文件命名与映射规则

| 文件类型 | 命名依据 | 映射规则 |
| --- | --- | --- |
| 角色 PDF | 角色姓名 | 生成角色、个人剧本、私有知识库。 |
| 线索图 | 数字序号 + 目录轮次 | 生成线索编号、所属阶段和展示顺序。 |
| 个人线索图 | 数字序号 + 角色姓名 | 绑定对应角色权限。 |
| 音频 | 序号 + 剧情名称 | 绑定阶段、事件和播放顺序。 |
| 人物海报 | 角色姓名 | 绑定角色头像和选角页。 |
| 道具图片 | 道具名称 | 绑定线上证物 / 道具记录。 |
| 卡牌图片 | 卡牌类型 + 序号 | 绑定技能卡、道具卡和默认使用规则。 |

### 16.3 导入后的人工审核重点

| 审核项 | 原因 |
| --- | --- |
| OCR 是否准确 | 线索图文字错误会直接影响推理。 |
| 角色姓名是否一致 | “崔铠强 / 崔凯强”等异体或错字需要别名映射。 |
| 隐藏角色是否确认 | “程俊.JPG”在当前 PDF 清单中未对应，需要确认用途。 |
| 下载中文件是否补全 | `.baiduyun.p.downloading` 不应进入正式发布。 |
| 音频是否有字幕 | 玩家静音或无法播放时仍能理解剧情。 |
| 售后资料是否隔离 | 防止 DM 资料、真相资料提前泄露。 |

### 18.1 当前已发现的素材问题

| 问题 | 影响 | 建议处理 |
| --- | --- | --- |

### 18.2 不应自动处理的内容

以下内容不应在没有人工确认的情况下自动发布给玩家：

- 最终演绎要点。
- 带本要点。
- 完整真相。
- 角色私密剧本。
- 个人线索。
- 未完成下载的人物海报。
- 未 OCR 校对的线索图。
